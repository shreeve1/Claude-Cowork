# Going back

An update never changes the current workspace: it builds a new one next to it. Going back means using the previous folder again.

1. **Owner decision:** confirm they want the previous workspace back.
2. Point the owner's agent app at the previous workspace folder again.
3. Anything the owner wrote in the new workspace after the update (new notes, documents) is not in the previous one. List those files by date for the owner and copy across only what they ask for, following `MIGRATING.md` step 2 (from the Release; the workspace has no setup folder) for where each goes.
4. Leave the new workspace in place until the owner says to delete it.

If the previous workspace was already deleted, set up again from the older Release with its `INSTALL.md`, migrating from the new workspace.
